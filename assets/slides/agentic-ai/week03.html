The case

A big 'ole plant community ecology dataset

Peter Marks's Finger Lakes Vegetation Survey, the basis of his Guide to the Plant Communities of the Central Finger Lakes Region. The paper sheets turned up in January, in a Cornell office cleanout. The digital files survived on backup CDs kept from 1994 to 2006.

181tenth-hectare stands: forest, swamp, fen

What we asked

The prompts

A — the task, in full

These files came off backup CDs from a vegetation survey of the central Finger Lakes region of New York. About 180 plots of forest, swamp and fen were sampled between 1973 and 1992, recording the woody layer, the ground layer and the site environment. The spreadsheets were assembled by several people over the 1980s to 2000s. A four-page methods chapter and a per-stand index are in docs/. The original files are in raw/.

I want to use this survey as the baseline for a resurvey of the same plots. Turn it into a clean, analysis-ready dataset.

When you are done, write a short report as a single self-contained HTML file, report.html, for a graduate seminar with a wide spread of background: what is in the data, what you did to it, and what you could not resolve.

R — the task, plus this

Someone who was not here, including a future version of me, has to be able to reconstruct exactly what you did and why. Raw files are read-only. One command rebuilds everything. Keep a decision log: what you decided, the evidence, the alternative. Where the files do not settle a question, do not guess: flag it. A data dictionary. Tests that would fail if a step went wrong.

Five runs, all Opus 5.5

A once. R twice, byte-identical. Then a fresh agent gets only the notes each of A and R left behind, no code and no outputs, and tries to rebuild their dataset.

Then the agent checked our work

One code, two plants

The woody file and the ground-layer file each have their own list of four-letter codes. Six codes mean a different plant in each list. Join the two layers on the code alone and a silky dogwood becomes a hazelnut.

CodeWoody fileGround-layer file
COAMCornus amomum, silky dogwoodCorylus americana, hazelnut
PYCOPyrus coronaria, crabapplePyrus communis, pear
ROSPRosa sp.Rorippa sp., a mustard

Three of the six shown. Our earlier cleaning made exactly this join: 18 woody records got the wrong species, and 11 roses became a mustard. It is not in the answer key because we did not know about it.

Caught it

A and R: kept each file's own code list.

Made it worse

R-rep: looked at COAM, decided dogwood and hazel were the same plant, and merged them without saying so.

A stranger with only the notes

Rebuilt from the notes alone, no code: R: 92% of cells. A: 82%. Both missed on the same thing, cover for plants seen outside the quadrats. A never wrote its choice down. R wrote it down wrong, and the rebuild believed the notes.

Takeaways

What we learned

  1. The code reproduces; the agent doesn't. Every run rebuilt byte-identical from raw. The same prompt run twice still wrote Python once and R once, and split on 425 cover values and on the code collision.
  2. The prompt bought a paper trail, not correctness. Tests that catch breakage, a decision log, open questions flagged rather than guessed. R-rep had all of it and still made a silent break.
  3. Notes are only as good as they are right. A stranger rebuilt 92% from R's notes and 82% from A's. R's notes described one choice wrongly, and the rebuild followed them.
  4. It broke on which plant is which. Both silent breaks were taxonomy, not arithmetic. Check there first.
